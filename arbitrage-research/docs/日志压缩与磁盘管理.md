# 日志压缩与磁盘管理

更新：2026-11-21。适用范围：`paper`监控及`data/live_monitor/`，包含原策略与候选策略。

## 新数据如何保存

原始消息`raw/`、规范事件`events/`、逐笔条件检查`signals/`均使用gzip无损压缩。250毫秒十档盘口快照、原成交事件、信号检查字段和时间戳均保留；没有降低采样频率、合并交易或删掉被拒信号。

按UTC日期/小时分区。每次重启使用新的`part-NNN.ndjson.gz`，防止异常退出留下的不完整gzip影响后续文件。已打开的分区加文件锁；压缩历史时跳过占用中的分区。

小体积的`paper/`、`health/`、`sessions/`继续使用原格式。候选十二本账户共用一份压缩观察，账户交易与结算追加账本保持原格式。候选观察也已使用每次启动独立的`HH.part-<唯一编号>.ndjson.gz`并持有写入锁，旧版`HH.ndjson.gz`保留。此改动不重置统计或修改策略规则。

停止命令只先通知采集解释器，允许最多约30秒等待网络请求、账本刷新和gzip收尾，完成后再关闭screen；超时会提示继续检查，不强制终止。不要直接关闭screen外壳代替`./arb-monitor stop paper`。

2026-11-21候选观察中断文件的专项修复、原件备份位置与操作命令见[候选监控漏秒与日志修复](候选监控漏秒与日志修复_20261121.md)。

## 历史日志无损压缩

在项目目录执行：

```sh
./arb-monitor compact          # 只预览文件数量和待处理体积
./arb-monitor compact --apply  # 逐文件压缩、校验、替换
```

只处理`data/live_monitor/events/`和`signals/`中符合日期/小时分区格式的普通`.ndjson`文件。拒绝符号链接和范围外文件；已有`.gz`若与原文件不一致会报错并保留原文件，不覆盖。

每个文件先写临时gzip，解压计算SHA-256、字节数、换行数，与原文件完全一致且原文件未改变后，才发布gzip并移除对应明文副本。原内容可完整解压恢复。先落盘校验清单再移除明文，清单在`data/live_monitor/storage_archive_manifest.ndjson`；中断后可重跑。失败时停止，不自动清空历史。

首次使用必须先升级并重启旧版监控，使写入器参与文件锁协议。本次已完成。之后可边采集边压缩；归档过程中暂不要同时启动扫描全目录的回测，避免格式替换瞬间同时读到一份明文和一份gzip。

已有增量回测缓存、主要研究脚本及导出器支持`.ndjson`和`.ndjson.gz`混读。通用事件读取与Parquet转换也支持gzip。文件格式迁移后，增量缓存可能需要扫描一次新路径；并非丢失样本或改变收益口径。压缩减少磁盘与读取字节量，不保证所有回测更快，解压仍消耗CPU。

## 页面余量提醒

原策略与候选Tab上方均显示数据所在磁盘的剩余空间。启动时检查，以后每60秒在工作线程检查一次，不逐秒遍历历史文件。

| 等级 | 任一条件满足时触发 |
|---|---|
| 空间偏低 | 剩余不足20GiB，或不足磁盘总容量10% |
| 空间紧张 | 剩余不足5GiB，或不足总容量2% |
| 无法检查 | 检查失败，显示未知状态，不能当作空间正常 |

提醒以文字和颜色共同表示，使用可被辅助设备播报的告警区域。健康日志仅在等级变化时追加一次，避免每秒重复记录告警。

这是容量提醒，并非硬容量上限。系统继续采集，不自动删除历史或悄悄停采；长期数据仍会增长。其他应用占用磁盘也会影响余量。接近紧急阈值时，可用`./arb-monitor stop paper`暂停本监控，或`./arb-monitor stop all`停止全部采集器，再迁移数据到更大磁盘。

本次处理的文件数、压缩前后体积和实际释放空间见下方执行记录；后续日增长以实际运行测量为准。
