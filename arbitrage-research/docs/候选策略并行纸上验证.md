## 页面和运行

在 `arbitrage-research` 目录执行：

```sh
./arb-monitor start paper
./arb-monitor status
./arb-monitor stop paper
```

已在运行时升级代码：`./arb-monitor restart paper`。页面 `http://127.0.0.1:8765/#candidates`，点击「候选策略 · 并行验证」。切换Tab和关闭浏览器都不会停止后台；停止 `paper` 会同时关闭原策略、六候选及候选专用Binance连接，不会关闭另行运行的cross/cross15/gate。全部关闭：`./arb-monitor stop all`。

候选跟随纸上监控启动，不需要钱包、私钥或启动实盘程序。原策略及旧账本保留。候选单独连接一次Binance Spot，补齐最近500根1分钟K线后维护递推指标；Polymarket盘口与官方结算复用现有监控，不按策略数量重复采集。

首次准备独立依赖环境（项目需要Python 3.11或更新版本）：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
```

控制脚本优先使用项目`.venv/bin/python3`，也支持`ARB_RESEARCH_PYTHON`覆盖。代理沿用`ARB_RESEARCH_PROXY`，默认`http://127.0.0.1:7890`；网络不可用会显示重连或缺数据，不把缺数据当策略失效。

## 冻结候选

| 版本 | 入场方向信号 | 成本上限 | 对照来源 |
|---|---|---|---|
| S1_net 翻转保守 | 已收盘1分钟Supertrend ATR10×3真实翻转 | 每份含费成本≤0.50 | T074原范围保守版 |
| S1_gross 翻转常规 | 同上 | 每份名义价≤0.50 | T074原范围常规版 |
| D1 | Spot相对本场Binance开盘价方向，距离时间分数≥1 | 每份名义价≤0.50 | T074原范围D1 |
| S3 | D1且1分钟Supertrend ATR14×3已确认方向一致 | 每份名义价≤0.50 | T071 S3 |
| A5 | ATR归一化锚定距离z≥1买UP、z≤−1买DOWN | 每份名义价≤0.50 | T068 A5 / T073 BOTH |
| A6 | ATR归一化锚定距离z≥1.5买UP、z≤−1.5买DOWN | 每份名义价≤0.50 | T068 A6 / T073 BOTH |

所有版本均做UP和DOWN，每个账户双向共享资金和倍投进度。初始趋势方向只是递推种子，观察到真实翻转后才确认趋势。Wilder ATR/Supertrend计算与冻结研究脚本做逐根比对。

D1分数为`abs(Spot − 本场精确Binance开盘价) / (ATR14 × sqrt(剩余秒数/60))`。锚点仅接受对应5分钟起点的1分钟K线open，不能拿附近成交代替；这不是Chainlink官方结算锚点。胜负只采用现有Polymarket官方结算事件。

A5/A6严格沿用T068的方向公式：`z = ln(Spot / 本场精确Binance开盘价) / (ATR14 / Spot)`，其中ATR14来自已收盘1分钟K线的Wilder平滑。两者阈值分别为±1.0、±1.5，不除以剩余时间平方根，不要求Supertrend确认或翻转；仍遵守共同时间窗口与成交限制。旧报告采用较早的K线公布时序，当前统一延后至少1秒可用，不能承诺复现旧报告笔数与成绩。

## 执行和账户

- 共用条件：决策时剩余270–30秒，卖一0.30–0.50；已收到完整盘口，盘口来源时间和接收时间均≤2秒；D1/S3/A5/A6另外要求Spot来源、接收时间均≤2秒。
- 每秒判断一次；只使用已收到的收盘K线，最早收盘后1秒生效；原收盘后60秒到期，不因网络晚到延长。
- 决策时逐档检查完整预算。提交模拟订单至少300ms后，使用当时观察到的盘口再检查。来源时间缺失、深度不足、市场切换/结束、执行晚于计划超过1秒都记未成交，不使用未来更好的盘口补这次订单。
- 每策略、账户、市场、方向最多一次提交；单账户同时最多一笔订单或持仓。未提交前深度不足可继续等待；已提交未成交不在该方向补单。执行时变便宜允许成交，不用未来最低价过滤撤销成交。
- 固定账户各100U虚拟本金，每笔含费预算1U。倍投账户各2047U虚拟本金，1、2、4…1024U共11档，放大后重新吃盘口，绝不是按1U收益直接乘倍数。
- 份额向下取整到0.01；完整预算允许最多0.01U余量。保守版每一档价格都满足含费成本≤0.50，不能仅靠平均价达标。
- 赢单或第11次亏损后回到1U；余额不足下一档时暂停新单。赢单不等于整个倍投周期必然盈利，页面单列赢单后周期仍亏和11连亏周期次数。
- 只有收到官方结算才更新胜负、资金和档位。上一场结束至少60秒，且官方结果已收到，才允许下一笔。
- 净收益：胜=`份额−本金−费用`，负=`−本金−费用`。回撤按已结算净值，持仓浮亏未纳入。收益率分母为累计实际投入含费用。

为延续历史对照，模拟费用系数冻结为0.07，每份`0.07*p*(1-p)`；页面明确标注它不是当前实际收费承诺。历史上每秒回放和现在收到数据后每秒评估存在时序差异，当前额外记录实际执行延迟与漏秒，纸上成交不能证明实盘成交。

执行差异也需保留：历史倍投回放先提取1U候选再按大额预算拒绝；本模块各账户按当前预算独立等待决策深度满足后提交。因此固定与倍投可能在同场不同时间入场，不能宣称实时流水是旧历史流水的逐单延续。这里验证的是冻结方向规则在这套明确的前瞻执行口径下的表现。

## 存储、恢复与版本

数据目录：`data/live_monitor/candidates/v1/`。

| 文件 | 内容 |
|---|---|
| `accounts.ndjson` | 追加的提交、成交、未成交、官方结算、覆盖计数、网络状态；账户变更写入后刷新并fsync |
| `observations/YYYY-MM-DD/HH.part-<唯一编号>.ndjson.gz` | 按UTC小时分区，每次启动独立分片；入场窗口每秒一份共享压缩观察，含双方0.50以内卖盘、来源/接收时间、Spot、锚点、指标。旧版`HH.ndjson.gz`仍保留 |
| `binance_state.json` | 递推指标与精确开盘价的原子检查点；Spot重连后必须重新收到，不能复用旧价冒充新价 |

原始Polymarket采集仍在原目录，不给每账户重复保存。候选计算和文件写入交给单独工作线程；网络流只提供内存快照。额外磁盘量取决于盘口档数，以实际文件增长测量，不承诺固定用量或零延迟影响。

观察分片持有写入锁，正常停止会完成gzip尾部；读取活跃文件使用`read_partition_rows`，允许尚未结束的活跃流。离线文件缺尾部仍报错，不自动忽略历史损坏。异常退出后的新进程不会继续追加旧分片；旧版中断文件可在停止`paper`后显式修复，详见[漏秒与日志修复记录](候选监控漏秒与日志修复_20261121.md)。

原监控高频`events`/`signals`也已改为无损压缩；页面上方统一显示数据盘余量，低空间提醒不停止策略或重置账户。历史压缩命令和校验记录见[日志压缩与磁盘管理](日志压缩与磁盘管理.md)。

重启从追加账本恢复独立账户、待结算市场、档位和首次尝试记录。过期的待执行单计未成交，不拿重启后的报价假装当时成交；未结算仓位继续补官方结果。日志损坏或未知规则指纹时暂停候选模块并显示错误，不能悄悄重置资金统计。改已有规则须升版本、换目录。

本次只做候选注册表的增量扩展，原四个方向与执行规则完全不变，因此沿用v1目录和原账户ID。加载器仅明确兼容旧四候选的冻结指纹`80df1440807513341a35c1d4dc1da707c232f4ba24304efebd3665997916edaa`和当前扩展指纹，旧指纹不得包含A5/A6。首次扩展追加`ACCOUNT_STARTED`事件，保存账户启用时间；新账户初始余额100U/2047U，收益、档位、胜负从零开始。其余指纹变化依然拒绝加载。每秒共享观察仍只写一份，新增量主要是四本账户的订单/结算事件。

## 如何评价新数据

每周看成交次数、已结算数、净收益、回撤、连续亏损、分方向结果和行情覆盖。固定与倍投分别看，不合并六策略重叠收益。A5/A6开始更晚，比较时需取相同观察时段。没有数据的时段不算没有机会，未结算不算失败，前期没有订单也可能是条件不满足。先冻结参数积累新样本；一周不自动证明策略有效，也不因几个100%胜率样本直接升级实盘。
