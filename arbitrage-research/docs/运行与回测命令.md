# 运行与回测命令手册

本文集中放可执行命令；项目入口 README 只保留最常用的三条命令和导航。

## 1. 实时监控

在项目根目录执行：

```bash
./arb-monitor start          # 启动 paper、5分钟 cross、15分钟 cross15、gate
./arb-monitor status         # 查看 screen 会话、状态、更新时间和错误
./arb-monitor compact        # 预览可无损压缩的历史事件/信号日志
./arb-monitor compact --apply # 校验后替换为gzip，保留全部内容
./arb-monitor restart paper  # 重启单个监控器
./arb-monitor start cross15  # 单独启动15分钟跨市场采集
./arb-monitor stop cross15   # 停止15分钟跨市场采集，保留数据
./arb-monitor attach paper   # 进入日志；Ctrl-A、D 脱离但不停止
./arb-monitor stop gate      # 停止单个；不会删除 data/
./arb-monitor stop           # 停止全部
```

`paper`同时启用原策略和「候选策略」Tab，后者为四候选×固定/倍投八本独立账户；无需另启cross，候选自带共享Binance Spot连接。[规则、账本和恢复说明](候选策略并行纸上验证.md)。

`paper`新增高频日志已使用gzip无损压缩，页面每60秒检查磁盘余量并提醒。历史压缩、校验清单和阈值见[日志压缩与磁盘管理](日志压缩与磁盘管理.md)。停止命令先通知进程完成账本和gzip收尾，再关闭screen；未及时退出会报告失败，不强制截断文件。

四个名称的含义：

| 名称 | 内容 | 输出 |
|---|---|---|
| `paper` | Polymarket 官方行情、UP/DOWN 纸上成交 | `data/live_monitor/`，页面 `http://127.0.0.1:8765` |
| `cross` | 5分钟 Binance Spot/Futures、Hyperliquid、Deribit、RTDS/Gamma | `data/cross_market_validation/` |
| `cross15` | 15分钟 Binance Spot/Futures、Hyperliquid、Deribit、RTDS/Gamma | `data/cross_market_validation_15m/` |
| `gate` | Gate 官方 WebSocket 辅助对照 | `data/gate_monitor/` |

三者均为观察/纸上模式，不使用钱包、私钥或真实下单接口；重启会继续追加已有分区文件。默认代理为 `http://127.0.0.1:7890`，临时更换：

```bash
ARB_RESEARCH_PROXY=http://127.0.0.1:xxxx ./arb-monitor start
```

`cross15` 还会同步采集15分钟 Polymarket 官方 Market WebSocket：

- `polymarket_snapshots/`：每秒UP/DOWN合并盘口摘要，包含10份买卖VWAP、最坏价、盘口年龄和多个价格上限内深度；
- `polymarket_trades/`：官方 `last_trade_price` 成交事件；
- 两者均按UTC日期/小时分区并使用gzip压缩；不保存完整原始WebSocket帧；
- 只采集、不下单，现有5分钟纸上交易策略不受影响。

可用下面的命令确认新数据是否持续写入：

```bash
find data/cross_market_validation_15m/polymarket_snapshots -type f -print
find data/cross_market_validation_15m/polymarket_trades -type f -print
```

### 1.1 screen 直接操作

```bash
screen -ls
screen -r arb-paper
# Ctrl-A，再按 D：脱离但继续运行
screen -S arb-paper -X quit
```

通常优先使用 `./arb-monitor`，只有故障排查时才直接操作 screen。

### 1.2 状态判定

`./arb-monitor status` 应看到：

```text
paper status=live
cross status=running
gate  status=live
```

更新时间应持续刷新，`error=-` 表示没有记录错误。不要为了重启删除 `data/`；历史数据和纸上账本会继续保留。

状态文件如果超过 120 秒没有更新，即使旧状态仍写着 `running/live`，`./arb-monitor status` 也会显示 `stale`。这表示旧数字，不代表进程仍在采集；需要重新执行对应的 `./arb-monitor start cross15`（或 `start paper/cross/gate`）。

## 2. 实时增量回测

监控运行期间，增量验证只处理新增的“已结算市场 × 策略”，会复用 SQLite 索引：

```bash
PYTHONPATH=src python3 scripts/analysis/run_incremental_live_strategy_validation.py
```

策略参数统一在 [`configs/research/live_strategy_cases_v1.json`](../configs/research/live_strategy_cases_v1.json)：方向、价格区间、剩余秒数、数量、触发方式、最坏成交价、盘口新鲜度和手续费都在这里定义。修改成交模型语义时要升级 `EXECUTION_MODEL_VERSION`，旧结果会自动失效重算，行情索引不必重建。

## 3. 历史回测命令

### 3.1 通用 CLI

```bash
PYTHONPATH=src python3 -m arb_research backtest \
  --events examples/prediction_events.ndjson \
  --config configs/strategies/last_2m_threshold.json \
  --out runs/demo

PYTHONPATH=src python3 -m arb_research quality \
  --input examples/prediction_events.ndjson --detailed
```

### 3.2 最后窗口 70–88 美分

```bash
PYTHONPATH=src python3 -m arb_research validate-last-window \
  --events data/markets/btc_5m_complete.ndjson \
  --out runs/last_window_70_88 \
  --windows 120,180 --price-min 0.70 --price-max 0.88 \
  --bucket-size 0.01 --price-source best_ask \
  --fee-model polymarket_crypto_taker --fee-rate 0.07
```

固定口径：使用可成交卖一价；每市场每方向取首次满足条件的报价；分别统计 ALL、UP、DOWN；输出样本数、胜率、Wilson 区间、机会率、平均入场价、盈亏平衡胜率和净 PnL。窗口覆盖缺口超过5秒的市场会被排除，`provisional=true` 的报告不能作为正式结论。

### 3.3 压力测试

```bash
PYTHONPATH=src python3 scripts/analysis/run_candidate_stress_test.py \
  --dataset combined=data/markets/btc_5m_official_trades_combined.ndjson \
  --chronological-split 0.7 --chronological-blocks 7 \
  --out runs/candidate_stress

PYTHONPATH=src python3 scripts/analysis/run_l4_depth_stress_test.py \
  --out runs/l4_depth_stress
```

L4 测试按限价逐档消耗盘口并计算 VWAP；若盘口未覆盖目标窗口，`coverageQualifiedMarketCount=0`，不能把它解释成“没有机会”。

### 3.4 E7完整生命周期补测与快速复核

E7完整模式覆盖已结算市场的剩余300–0秒八个时间窗，并保存逐规则明细；适合需要审计或导出原始行时使用：

```bash
PYTHONPATH=src python3 scripts/analysis/run_strategy_idea_e7.py
```

日常只想快速看最近时间外结果时，使用汇总模式，不生成近百万条明细：

```bash
PYTHONPATH=src python3 scripts/analysis/run_strategy_idea_e7.py \
  --split validation --summary-only \
  --out outputs/research_tests/e7_quick_validation
```

`--summary-only`只省略逐笔明细，不改变入场、退出、VWAP、手续费或结算口径；之后需要审计时仍可运行完整模式。`--split validation`只读取时间外验证市场，避免每次重复解析旧训练数据。

短周期回落动能验证可在同一脚本中覆盖1/2/3/4秒和原有5/10/15/30秒基线；建议先用汇总模式：

```bash
PYTHONPATH=src python3 scripts/analysis/run_strategy_idea_e7.py \
  --split validation --summary-only \
  --reversal-horizons 1,2,3,4,5,10,15,30 \
  --reversal-drops 0.01,0.02,0.03,0.05,0.08,0.10,0.15,0.20,0.30,0.40,0.50,0.60 \
  --experiment-name E9短周期回落动能验证 \
  --out outputs/research_tests/e9_short_horizon_momentum_20260826
```

该命令只新增离线研究产物，不会修改纸上交易或实盘策略配置。

固定策略交叉对照（基线、单独加入动量、Binance Spot、E0，并统计排除的失败/成功单）：

```bash
PYTHONPATH=src python3 scripts/analysis/run_strategy_idea_e10.py
```

成熟策略一/二/三因子组合，以及Binance相对开盘距离+剩余时间概率验证：

```bash
PYTHONDONTWRITEBYTECODE=1 python3 scripts/analysis/run_strategy_combo_matrix.py
PYTHONDONTWRITEBYTECODE=1 python3 scripts/analysis/analyze_binance_distance_probability.py
PYTHONDONTWRITEBYTECODE=1 python3 scripts/analysis/compare_down_momentum_binance.py
PYTHONDONTWRITEBYTECODE=1 python3 scripts/analysis/analyze_current_strategy_time_factors.py
```

第二个命令会用前70%市场拟合概率表、后30%时间外验证，并把概率门槛逐档加入成熟策略；第三个命令专门比较DOWN的5秒动量与严格Binance 5分钟方向；第四个命令按方向、时段和星期生成参考分层；均不会自动修改纸上交易或实盘配置。

全时间轴严格正向首次突破网格（剩余300–0秒每20秒一档、阈值0.50–0.90，排除回落触碰）：

```bash
PYTHONDONTWRITEBYTECODE=1 python3 scripts/analysis/analyze_positive_upcross_time_grid.py
```

输出在 `outputs/research_tests/e16_positive_upcross_probability_20260830/`，包含中文报告、完整汇总CSV、逐笔信号CSV和JSON元数据。

历史幅度、本场幅度和即时状态概率计算器（E17）：

```bash
PYTHONDONTWRITEBYTECODE=1 python3 scripts/analysis/analyze_probability_amplitude_model.py
```

首版结果在 `outputs/research_tests/e16_positive_upcross_probability_20260830/e17_amplitude_probability/`；本场幅度使用离散E15特征快照，成熟策略对齐不足时只能做模型研究，不能直接作为实盘硬过滤。

## 5. 数据目录与保留边界

- `data/live_monitor/`：Polymarket 原始消息抽样、事件、信号、纸上成交、健康状态。
- `data/cross_market_validation/`：交易所每秒聚合快照、领先滞后事件、点时特征、官方结算标签。
- `data/cross_market_validation_15m/`：15分钟合约对应的交易所每秒聚合快照、领先滞后事件和官方结算标签。
- `data/gate_monitor/`：Gate 10秒压缩聚合和状态文件。
- `data/derived/live_strategy_cache.sqlite3`：增量索引和策略结果缓存。

页面状态文件只用于展示，不是回测事实源。实时内存队列会按时间和条数裁剪；累计消息数只是计数器。原始事件按小时 gzip 分区，长期运行仍应定期查看磁盘并归档。
